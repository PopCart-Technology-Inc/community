Community · staff panels · accepted 2026-10-21 · decision 0009

Run Community
without taking a single username.

Two panels for running Community. Overseer is the superadmin. Admin is for the people an Overseer invites: moderators, support and developers. Neither panel is on the public site, so community.popcartph.com/<username> always belongs to a person.

Usernames stay at the top

Profiles live at /<username>. Names like admin, overseer and their look-alikes are reserved, so nobody can pose as staff.

Panels sit behind a gate

They run on a separate staff host that's hard to guess. Cloudflare Access turns strangers away before a request reaches our server, and a staff passkey is still needed after that.

Two people for the big ones

Opening a sealed record, making an Overseer or opening joining to everyone needs a second Overseer. Every action leaves a trail.

03 · Security

Hidden is a curtain.
These are the locks.

Each lock still holds if the one before it fails.

1
A host name nobody can guess

A random first-level name such as ‹12 random letters›.popcartph.com, never admin. or staff.. It sits under the existing wildcard certificate, so it never shows up in the public certificate logs scanners read to find new hosts.

Curtain
2
A gate before our server: Cloudflare Access

The tunnel already runs through Cloudflare. Access lets in only staff email addresses on a list, after a one-time code. Everyone else stops at Cloudflare. The free Zero Trust plan should cover a team this size; confirm the user limit at setup.

Lock
3
The server checks the gate's signed token

Every staff request must carry Cloudflare's signed token (Cf-Access-Jwt-Assertion) and the staff host name. Anything else gets a 404. The public host has no staff API at all.

Lock
4
A staff passkey tied to that host

Passkeys are bound to the host they're made on. The staff host has its own passkey and its own __Host- cookie, so a member session or a phishing site can't get in.

Lock
5
Scopes, a log and alarms

A role can do only what its scopes allow. Every action is logged, append-only. Repeated failures at the gate or the passkey step alert the Overseers.

Lock
● Secondhand: third-party guides, not Facebook's help pages

How Facebook handles usernames

Guides say Facebook usernames need at least 5 characters, may use letters, digits and periods, and that periods and capital letters don't make a name different: john.smith55 and JohnSmith55 count as one name. Generic words are refused. I found no public list of the exact reserved words.

We copy this: dots, underscores and look-alike digits don't make a name different.

● Confirmed for the user tools; staff tools unconfirmed

How Facebook separates admin tools

The tools users run Pages and ads with live on their own subdomain, business.facebook.com, not under anyone's profile path. Staff-only tools aren't publicly documented. They're widely reported to sit on an internal domain that only company devices can reach, but I couldn't confirm that from a public source.

We copy this: a separate host that only invited staff can reach.

04 · Roles

Four levels.
Roles are lists of scopes.

Space owners and moderators stay inside their own Space (decision 0003). Platform staff are new. The server checks scopes such as reports.review, never a role name, so adding a role needs no new code.

Level 0Member

Everyone. Posts, joins Spaces, takes gigs. Can report anything and see who opened their records.

07 · Decided

Three decisions, made.

How many Overseers?

Two: you and one person you trust. The two-person rule needs a second Overseer. Until there is one, those actions go through the server command line.

Which roles to start with?

Moderator, Support, Developer. Trust & Safety and Space verification can come later as new scope lists, with no code change.

A public staff badge?

No. Staff keep plain profiles, and official notices come from the reserved @community account. Nobody can be targeted as staff, and there's no badge to fake.
